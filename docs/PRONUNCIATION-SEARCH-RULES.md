# Pronunciation & Sound Search Baseline

> Status: locked baseline  
> Purpose: 초기 Sound to Script 기획에서 합의한 “한국어로 들린 일본어 → 실제 일본어 표기” 규칙을 검색엔진 변경과 무관하게 유지한다.

## 1. Core principle

사용자 입력은 정확한 일본어 철자가 아니라 **한국어로 기억한 들린 소리**다.

따라서 검색은 철자 오타 교정이 아니라 다음 순서로 처리한다.

`Heard Korean Sound → Pronunciation Variants → Japanese Context / Grammar → Verified Script → Meaning`

발음 변형은 후보를 넓히기 위한 수단이고, 최종 결과는 일본어 문법·표기·뜻이 자연스러운 후보를 우선한다.

## 2. Baseline pronunciation rules

### 촉음 っ

- 검색에서는 촉음 누락/과잉을 모두 가까운 청취 후보로 본다.
- 사용자에게 보여주는 한국어 발음에서는 **앞 음절의 ㅅ 받침**으로 통일한다.
- ㄱ 받침 표기는 사용하지 않는다.

Examples:

- `きっと → 킷토`
- `ずっと → 즛토`
- `もっと → 못토`
- `フラッシュ → 후랏슈`

### 장음

사용자는 장음을 빼고 기억할 수 있다.

- `どうして`를 `도시테`로 입력해도 후보에 포함
- `きょうはん`을 `쿄한`으로 입력해도 후보에 포함
- `とうきょう` 같은 익숙한 표현의 한국어 발음은 불필요하게 모음을 늘이지 않고 `도쿄`처럼 표시

장음 복원은 후보 생성 단계에서 수행하고, 장음이 있다는 이유만으로 입력을 틀렸다고 단정하지 않는다.

### 청음 / 탁음 / 유사 자음

한국어 청취에서 다음 계열은 흔들릴 수 있다.

- k ↔ g
- t ↔ d
- p ↔ b
- s ↔ z
- shi / ji / chi 계열

발음이 비슷하다는 이유만으로 확정하지 않고, 전체 문맥과 일본어 문법으로 랭킹한다.

### 된소리 / 강한 자음

한국어로 적을 때 `꼬 / 또 / 빠 / 싸 / 짜`처럼 강하게 기억할 수 있다.

검색에서는 이를 완화한 후보도 함께 본다.

Example:

- `도코에이꼬` → `도코에이코` 계열도 비교

### ん

`ん`은 한국어로 기억할 때 ㄴ/ㅇ 계열로 흔들릴 수 있다.

- 검색에서는 비음 차이를 허용
- 결과 표기는 검증된 표현의 실제 읽기를 기준으로 제공
- 특정 단어의 자연스러운 한국어 발음이 정해져 있으면 curated pronunciation을 우선

### 요음

작은 `ゃ / ゅ / ょ`는 분리하지 않고 한 덩어리로 표시한다.

- `きょ → 쿄`
- `しゃ → 샤`
- `しゅ → 슈`
- `りょ → 료`

### 조사 발음

표기와 실제 발음이 다른 조사를 검색에서 동일하게 연결한다.

- `は` (조사) → wa / 와
- `へ` (조사) → e / 에
- `を` → o / 오

Example:

- `どこへ行こう` → `도코에 이코`
- `今日は`의 조사 `は`는 실제 소리 `わ`와 연결

## 3. Phrase / context rules

### 붙여쓰기

사용자가 띄어쓰기를 몰라도 검색을 막지 않는다.

- 단어를 무작정 독립 검색하지 않는다.
- 전체 일본어 구문을 먼저 본다.
- 필요할 때 단어 + 조사 + 활용 경계를 복원한다.

Example:

`도코에이코 → どこ + へ + 行こう → どこへ行こう`

### 문맥 우선

`쿠테 / 구테 / 쿳테 / 굿테`처럼 여러 발음 후보가 가능할 때:

1. 가까운 청취 후보군을 생성
2. 앞뒤 소리 전체와 비교
3. 실제 일본어 활용·문법이 성립하는지 확인
4. 문맥상 자연스러운 후보를 상위에 배치

짧은 입력만으로 확정할 수 없으면 여러 후보를 보여줄 수 있지만, 틀린 후보를 “맞는 표현”이라고 단정하지 않는다.

## 4. Result policy

결과 위계:

`일본어 원문 → 히라가나 읽기 → 한국어 발음 → 자연스러운 한국어 뜻`

- 자동 생성된 한국어 발음은 “정답 교정”의 근거로 쓰지 않는다.
- 검증된 canonical pronunciation이 있을 때만 권장 표기로 사용한다.
- 정확 후보가 없더라도 검색을 바로 0건으로 끝내기보다 실존하고 가까운 후보를 별도 “가까운 후보”로 구분할 수 있다.
- IME/자동완성이 입력 뒤에 듣지 않은 단어를 붙인 prediction tail은 제외한다.

## 5. Regression contract

Production build에서 다음 baseline이 깨지면 실패하도록 유지한다.

- `きっと → 킷토`
- `ずっと → 즛토`
- `フラッシュ → 후랏슈`
- `とうきょう → 도쿄`
- `도시테 → どうして` 가능성
- `쿄한 → きょうはん` 가능성
- `도코에이꼬 → 도코에이코` 발음 완화
- `쿠테 / 구테 / 쿳테 / 굿테` phonetic neighborhood
- 조사 `は → わ` 정렬
- 입력보다 긴 IME prediction tail 차단

이 문서는 새 검색엔진·LLM·랭킹 구조를 도입하더라도 바꾸지 않는 baseline이다. 규칙을 변경하려면 사용자와 별도 합의 후 문서와 regression test를 함께 수정한다.
